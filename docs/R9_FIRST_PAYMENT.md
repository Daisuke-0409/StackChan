# 初弾: スタバで実際に1杯注文する

2026-08-19 深夜作成。**実装は全部終わっている。明日やるのは実験だけ。**

## やる前に (大輔の手作業・5分)

1. **スタバカードに入金** — アプリかWebのPayタブから。1000円あれば十分
   (キャラメルワッフル 216円 / ミネラルウォーター 206円 が最安帯)
2. **カートを空にする** — 8/19夜のテストで
   「Tall 芳醇 巨峰 フローズン ティー」と「キャラメルワッフル×2」が
   残っている。残っていると `LeftoverCart` で止まる (それが正しい動作)。
   webapp の注文画面で消すか、注文して食べるか、どちらでもよい
3. **時間帯** — 宮崎の店は 21:55〜22:00 に受付終了。**昼間にやること**

## 決済を有効にする (1行)

`firmware\gateway\.env` に足す:

```
ORDER_PAYMENT_ENABLED=1
```

そして注文エージェントを再起動:

```powershell
powershell -File orderagent\run_orderagent.ps1
```

起動ログに `payment_enabled=True` が出れば有効。**これを戻せば練習モードに戻る。**

## 実験

タチコマに (実機でもメガネでもPCマイクでも) こう言う:

> スタバでキャラメルワッフルをテイクアウトで注文して

起きること:

1. 「了解、注文を準備するね」
2. 30〜60秒後、読み上げ:
   「宮崎神宮東店、キャラメルワッフル 1点、お持ち帰り、合計216円。
   注文は決済後キャンセルできないよ。注文していい？」
3. **「注文して」** と言う (「はい」だけでは通らない設計)
4. 決済が実行され、読み上げ:
   「注文できたよ。注文番号は◯◯、宮崎神宮東店で受け取ってね」

**中止したいとき**: 「キャンセル」と言う。5分黙っていても自動で流れる。

## 止まったときの読み方

| 読み上げ | 意味 | 対処 |
|---|---|---|
| カードの残高が足りないよ | 決済前に検出 (お金は動いていない) | 入金する |
| カートに前の注文が残ってるよ | 他人の注文と混ざるのを防いだ | ブラウザで空にする |
| ログインが切れているよ | セッション切れ | ブラウザで入り直す (素のChromeで) |
| 今どこも注文を受け付けてない | 営業時間外・受付終了後 | 時間を変える |
| 決済のボタンが効かなかった | **注文は入っていない** | もう一度言う |
| 決済の結果が確認できなかった | **不明。二重に押さない** | アプリの注文履歴を人が確認 |

最後の1行が肝心。**結果不明のとき、エージェントは絶対に押し直さない。**
1杯が2杯になる事故は、リトライからしか生まれない。

## モスも使える (8/19 深夜に実装完了)

言い方: 「モスでモスバーガーを注文して」

- **大輔のアカウントでログイン済み** (ゴールドランク・モスカード残高1,438円)。
  **注文用ブラウザのウィンドウは閉じないこと** — モスはブラウザを閉じると
  ログアウトする (「ログイン状態を保持する」が無い)。最小化はOK
- 高鍋店が2.4km。職場なら宮崎大島バイパス店
- カートは自動で空にしてから積む (スタバと違い削除ボタンがある)
- 決済は**未実装**。スタバの初弾が成功してから同じ形で足す

## 安全装置の一覧 (全部コードで強制)

- `ORDER_PAYMENT_ENABLED` 未設定なら全ジョブがドライラン
- 承認は「注文」を含む明確なフレーズのみ。5分で失効
- 読み上げは**サイトのカート実物**から生成 (こちらの意図ではなく)
- 決済直前にもう一度全額を突合。1円でも違えば中止
- 3,000円上限 (`ORDER_MAX_YEN`)
- プリペイド残高が足りなければ決済しない
- リトライなし
- 全遷移が `orderagent/data/orders.db` に監査記録
