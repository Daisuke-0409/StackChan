# CRM 照会 API — 確定した契約

CRM 側の実装完了報告 (2026-08-19、`daibo-sekizai-crm` の `5c681d2`、本番稼働中) を
タチコマ側の作業用にまとめたもの。依頼書は
[CRM_LOOKUP_API_REQUEST.md](CRM_LOOKUP_API_REQUEST.md) で、**こちらが実物**。
食い違ったらこの文書が正。

```
GET /api/tachikoma/lookup?name=<氏名>&asked_by=<照会者名>
X-Tachikoma-Token: <トークン>
```

## 依頼書との違い (2点、読み上げの実装に効く)

### 1. `area` は「区画」ではなく「地区」

依頼時に区画番号だと思っていたものは、実際にはこう入っている:

| 項目 | 中身 | 例 |
|---|---|---|
| `cemetery_name` | 霊園名 **＋ 区画番号** | `みたまC-3-57` / `宮崎霊園B1-139` / `専唱寺` |
| `area` | **地区・エリア名** (市町村内の区域) | `田野` / `綾` / `佐土原` |
| `zenrin_map_no` | 紙のゼンリン地図の図番 | `12-I-4` |

**区画番号は `cemetery_name` の中にある。**`area` が空なのは墓所 2,090 件中 **773 件 (36%)** で、
これは異常ではない。読み上げで「区画が分かりません」と言ってはいけない。

読み上げの形:

```
cemetery_name + (area があれば 「（{area}地区）」)

  みたまA-12                 → 「みたまA-12 です」
  専唱寺 + 郡司分            → 「郡司分地区の専唱寺 です」
```

`zenrin_map_no` は紙地図の索引なので**声では読まない**。
そのため `crm_relay.py` の `ALLOWED_FIELDS` からも外してある
(表示したくなった日に1行戻せばよい)。

### 2. 同じお墓の重複は CRM 側で畳まれている

同一人物が同じ墓で複数回発注しているケース (追加彫刻など) が台帳に多数ある。
CRM は **4項目が完全一致する行を1件に畳んでから** `count` を数えている。

- `count` は**別々のお墓の数**であって、案件数ではない
- したがって**タチコマ側で重ねて重複排除してはいけない** — 畳む基準が
  こちらの方が粗い (`zenrin_map_no` を持たない) ので、別の墓を1つに潰す

## 応答

```json
{
  "count": 6,
  "results": [{"customer_name": "…", "cemetery_name": "…",
               "area": "…", "zenrin_map_no": "…"}]
}
```

`count` は総数、`results` は先頭3件まで。`count > 3` なら
「6人いるので絞って」と言える。該当なしは `{"count": 0, "results": []}` (エラーにしない)。

**この4項目以外は返らない。**住所・故人名・受注日・施工者名・写真・座標はキー自体が無い。

## ステータス

| コード | 意味 | 相手 |
|---|---|---|
| 200 | 正常 (0件も200) | |
| 400 | `name` が空・未指定 | こちらのバグ |
| 403 | **トークン不一致・未指定** | 設定ミス |
| 401 | GET 以外で叩いた | こちらのバグ |
| 501 | HEAD で叩いた | **ヘルスチェックに HEAD を使わない** |

`GET` のみ。`crm_relay.py` は 403 と 404 を別々に報告する
(トークンが違うのか、エンドポイントが無いのかを取り違えないため)。

## 認証

- `X-Tachikoma-Token` の一致のみ。個人PINもセッションも不要
- 実体は CRM の `config.json` の `tachikoma_token` (32桁16進)。**git には入っていない**
- ローテーション: `config.json` の該当行を消して CRM を再起動すると再生成される
- `is_local()` には依存していない → **NAS 移設後もホストが変わるだけ**

## `asked_by`

声紋で識別した照会者名を渡す。**CRM 側は登録済み担当者名と完全一致で判定する**:

```
社長 / 会長 / ダイスケ / 篠崎 / 染川
```

(「大輔」は CRM 側で「ダイスケ」に統一済み)

一致しない・未指定でも**拒否されない**。`unknown` として処理が続き、その旨が audit_log に残る。
声紋が外れただけで現場が止まらないための設計。

## 監査

照会1回につき audit_log に1行、追記のみ。「誰が」「いつ」「誰を照会したか」。
書き換え・削除の API は存在しない。

## NAS 移設で変わるもの

**接続先ホストだけ。**`crm_relay.py` の `CRM_BASE_URL` を
`http://127.0.0.1:8765` → `http://<NASのホスト名>:8765` にする。
パス・トークン・ヘッダ名・レスポンス形式は変わらない。
移設が済んだ時点で、照会役そのものを消してゲートウェイから直接引ける。

## 今後こちらから依頼できるもの

**タチコマ側でレスポンスを増やす回避策は取らない** (最小開示が崩れる)。必要になったら CRM へ依頼:

- 座標 (`latitude` / `longitude`) — ナビ連携をやる段階で
- 住所での検索 — 声で住所を言う運用が出てきたら
- レート制限 — 現在未実装。連続照会で問題が出たら
- 書き込み — この API は読み取り専用。完了報告等が要るなら別途設計

- 2026-08-19 に、同じポートへ**二重起動できてしまう不具合**が修正された。
